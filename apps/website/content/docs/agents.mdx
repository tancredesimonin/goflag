An agent that edits a site's metadata, sitemap, `robots.txt` or hreflang cannot
see what it broke: the page renders, nothing fails, and the damage shows weeks
later in a search console. goflag can see it before the commit. The agent only
has to be told to look.

## The block to paste

Put this in the instructions your agent reads — `AGENTS.md`, `CLAUDE.md`, or
your editor's rules file:

```markdown title="AGENTS.md"
## SEO checks

Before committing a change to metadata, the
sitemap, robots.txt or hreflang, run
`pnpm seo:check` and fix every finding it
reports as new. `explain_rule <id>` in the
goflag MCP server, or the rule's page on
goflag.tech, says what the rule requires and
who requires it.
```

Instructions the agent reads every time do more than a skill it has to decide to
load: the check runs because the file says so, not because the agent remembered
it exists.

## The script it runs

The block names a script rather than a command, because the script carries what
an agent cannot guess: the shape the site has when it ships.

```json title="package.json"
{
  "scripts": {
    "seo:check": "goflag http://localhost:3100 --start \"APP_ENV=production NEXT_PUBLIC_SITE_URL=http://localhost:3100 next dev --port 3100\" --no-external --baseline .goflag/baseline.json --regressions-only"
  }
}
```

- **A baseline defines "new".** On a site with a backlog, "fix every finding" is
  a week of work; "fix what this change introduced" is the task. Without
  `--baseline` and `--regressions-only` ([Baseline gating](/docs/ci/baseline)),
  every finding the site already carries comes back as the agent's.
- **The production shape.** A site that keeps crawlers out of everything but
  production serves `Disallow: /` from its dev server, and goflag reports
  exactly that. Set the flag the site reads — `APP_ENV` here — so the audit
  sees the pages that ship.
- **The local origin.** Canonicals and `hreflang` are absolute. Built against
  the deployed origin, every alternate points off `localhost`, `--no-external`
  refuses to follow it, and the crawl never leaves the default locale. Set the
  variable the site builds its origin from to the URL goflag audits.
- **Its own server.** `--start` boots `next dev`, waits for it to answer,
  audits and stops it: seconds, where a build takes minutes, and the
  [merge-request job](/docs/ci) still audits the build. Port 3100 keeps it off
  the one you develop on, but Next runs one `next dev` per directory: with
  yours up, the script stops at once and prints Next's reason. Stop yours
  first.
- **One version.** `goflag` here is the pinned dev dependency
  ([Install](/docs/install#add-it-to-a-project)), so the lockfile holds the
  version and a dependency update moves it; keep it at the one your CI gate
  runs. `npx @goflag/cli` in an agent's shell takes whatever was published
  last, and a rule added since reads as a finding the change made.

Whatever else the merge-request job sets before it audits, the script sets too:
a data step that writes files the pages link to, a variable the config refuses
to start without.

Measured on a four-locale site that blocks indexing outside production:
`goflag http://localhost:3000 --json --summary` against `next dev`, with no
environment set, crawled five pages, all in the default locale, and failed on
`robots.blocks-site` and `sitemap.entry.cross-host` — the setup, not a change.
This script crawled 24, six per locale, and reported nothing new.

## Two ways in

- **The script**, for anything that runs a shell: the diff against the
  baseline, short enough to read whole, or the full report with `--json`
  appended.
- **[The MCP server](/docs/mcp)**, when the agent's client speaks MCP: typed
  tools, progress while it crawls, and each rule a call away. It runs no
  command, so the agent starts the server itself, in the same shape, then calls
  `compare_to_baseline` with `.goflag/baseline.json`.

Both run the same engine and return the same findings.

## What an agent gets to read

goflag is written to be read by something that has to act on it.

- **Every finding carries its rigor.** `spec-required` and `vendor-spec` are
  requirements; `guideline` and `heuristic` are advice. An agent can fix the
  first kind without asking and propose the second.
- **Every rule cites its sources.** `explain_rule`, or `goflag rules` for the
  whole catalogue as JSON, gives the documents behind a rule rather than an
  opinion about it.
- **Questions stay questions.** Five rules ask something a linter cannot decide
  — does the title describe the page, is it in the declared language. With
  `--advisories` (or `advisories` in `audit_site`) they come back with the
  evidence the agent needs to judge, and they never count toward the exit code.
